# Bounded continuous discovery: query and pre-intro quality guardrails

24 October 2026, IST. Planning guidance for the newly human-authorized continuous-loop build/run. No discovery/provider/model calls or Git/runtime edits by this research chat. The reported run scope is 30 minutes, at most four new cases, 20 Crustdata requests, 50 credits and four model calls; control/backend own exact durable limits, execution and start status. This note does not assert a run has started or permit resetting allowances each cycle.

## Query quality

Use one short **task + user/problem + product/mechanism** hypothesis per query. Avoid long lists of sectors, generic healthcare growth/founder terms, or a chain of evidence/stage wishlists. Search relevance is a lead, not fit, proof of operation or founder quality. Actual performance of any mode/query remains observed rather than assumed.

| Existing track | Example query language, not a mandatory sector filter | Quick post-retrieval clarification |
|---|---|---|
| H | Software that automates referral intake or prior authorization for healthcare providers | What named workflow is performed, who uses it, and what is the reusable product versus general advice? |
| R | Software that quantifies microscopy images for cell-biology researchers | What concrete input/output or tool exists? Lab instruments/assays can be alternative R hypotheses; software is not required across the track. |
| D | Companies developing blood tests to monitor cancer-treatment response | What is the actual intended use? Monitoring, screening, treatment selection and analytical validation must not be conflated. Other test/device hypotheses remain eligible. |
| T | Biotechnology companies developing experimental therapeutic programs for a named disease | What indication/mechanism/program is described, and what work is measured versus predicted? Scientific proof/rights can remain call questions under the pre-intro overlay. |

These are alternative search hypotheses, not a distribution quota or four forced calls. A short query's example specialty does not narrow the whole mandate. Do not reject an otherwise useful case because its exact terminology or theme differs. If a result is services-led, look for an affirmative repeatable product/asset signal before prioritizing it; preserve legitimate software/services and experimental-platform partnerships rather than imposing a blanket services exclusion.

## Cheap normalization before expensive evaluation

Resolve the exact domain/project/company identity; retain original provider IDs and provenance. Deduplicate against existing nine, other current cases and prior run encounters. Known YC-backed entities are references rather than novel YC origination; unknown backing stays unknown. Do not merge similarly named tools or count a repeat as new. No new geography, revenue, pedigree, headcount or funding thresholds.

Read the actual product/program description rather than trusting the branch label. Require a concrete sourced description and a credible introductory reason, not a fully validated product. Generic consulting/marketing or a supplier without a concrete reusable offering can be research_first/outside_scope only on the actual evidence; missing coverage alone is not rejection. If no honest reason can be articulated, explain the shortfall rather than spending a model call merely to fill four cases.

## Stage and execution boundaries

Use the additive pre-outreach overlay for introductory merit and separate person/contact actionability. Private demonstrations, precise current contribution, rights/access and deep scientific/clinical validation are normally the introductory agenda. Known contrary identity/current-status facts still matter. Do not lift strict partner-review/qualification gates or imply sending is authorized.

Bind any proposed action to the current evidence/version and remaining authorized resources. A pursue recommendation creates an obligation to attempt its allowed next action or present human research points, not an infinite repeat. Record actual attempts and reassess accepted material deltas. Stop on the run's duration/budget/case/model boundary and retain honest unresolved cases. A time interval, budget pause or missing private document is not proof of negative company merit or a substantive monitor trigger.

## Overlay activation seam

Existing nine guidance is pinned to its saved v3 case/assessment/input refs and evidence hashes. Agents/backend can adapt that guidance to the pure pre_outreach mapper with the supplied raw overlay/guidance hashes and explicit provenance; check staleness and preserve the original interpretation record. Intro labels are never fresh model outputs. Contact status, strict readiness and qualification remain separate.

Do not copy the eight/one historical category distribution or case-name decisions to new discoveries. New cases need their own current source-bound rationale under the same human-authorized stage policy; the nine-case JSON is calibration/application evidence, not a template answer list. Runtime activation, data persistence, scheduling and the actual bounded run are owner work, not accomplished by saving this planning note.
