# Explicit fallback materials

1. **Backend available, provider unavailable:** keep HTTP transport. The foundation defaults to synthetic fixture discovery and requires no external key. Label the fixture evaluator and every record as synthetic. This path exercises real local persistence and HTTP integration.
2. **Backend unavailable:** Connection settings → choose **Browser fixtures · synthetic fallback** → Apply connection. Create and run a new placeholder mandate. This selects a separate browser-local store; it is never automatic. The fallback cast is Aster Loop, Boreal Works, and Cinder Systems, all invented. Replays append synthetic assessments; Boreal moves to monitor while verification and founder gaps remain. Aster has an illustrative review draft. Do not describe this as backend persistence or provider integration.
3. **UI demo interrupted:** use `demo/three-minute-script.md`, `demo/verification.md`, `demo/integration-report.json`, and saved screenshots if present. These document the synthetic harness only. No genuine captured Crustdata responses are supplied.

Switching back to HTTP restores the backend's independent data store. Reloading preserves data in the selected store. Browser fixture data is bound to its origin and browser profile; clearing browser storage removes only that fallback store.

The fallback does not establish the real Crustdata requirement. Human-reviewed reference v0.3 is now available; backend credentials and adapters are separate server concerns. A meaningful thesis-specific provider journey, approved runtime policy/projection and accepted genuine semantic assessment remain integration dependencies.
